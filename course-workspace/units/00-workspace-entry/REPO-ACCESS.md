# Unit 1 前的三个公开 Repo 检查

这三个 repo 已公开，不需要老师发送邀请。进入 Unit 1 前，只确认它们确实可以访问；不要一次把所有内容读完。

| Repo | 课程用途 | Unit 1 前要做到什么 |
| --- | --- | --- |
| [AI Agent Learning Workspace](https://github.com/franksong2702/ai-agent-learning-workspace) | 课程地图、Unit 和 Codex 提示词 | 已 clone 到个人 Obsidian 的 `Projects/AI Agent Learning Workspace/` |
| [AI Engineering Knowledge Base](https://github.com/franksong2702/AI-Engineering-KnowledgeBase) | 课程引用的 AI 工程知识来源 | 浏览器能打开 README；不要求现在读完整知识库 |
| [AI Pet Demo](https://github.com/franksong2702/ai-pet-demo) | Unit 4 网页开发脚手架 | 浏览器能打开 README；到 Unit 4 再 clone 到 `~/Projects/ai-pet-demo/` |

## 人检查

1. 在浏览器中逐个打开三个链接。
2. 确认页面显示 repo 文件列表，而不是 404、登录限制或网络错误。
3. 登录自己的 GitHub 账号。公开内容即使未登录也能读，但 Unit 4 的 fork 和 Pull Request 需要个人账号。
4. 任何一个打不开，都记录具体 repo、网址和页面错误，交给老师现场处理。

## 可以交给 Codex 的检查

```text
请只读检查下面三个公开 GitHub repo 是否可访问，不要 clone 后两个，不要 commit、push、fork 或创建 Pull Request：

https://github.com/franksong2702/ai-agent-learning-workspace
https://github.com/franksong2702/AI-Engineering-KnowledgeBase
https://github.com/franksong2702/ai-pet-demo

可以使用 git ls-remote 或其他只读方法。逐个报告：repo 名称、公开访问是否成功、默认分支、准确错误。不要向我索取密码或访问令牌。
```

## 重要区别

公开 repo 解决的是“能阅读和 clone”，不会自动获得向老师 repo 推送代码的权限。Unit 4 默认使用：

```text
fork 到自己的 GitHub 账号
-> 在自己的 fork 创建 branch
-> push 到自己的 fork
-> 向老师 repo 提交 Pull Request
```

这条路径不需要 collaborator 邀请。
