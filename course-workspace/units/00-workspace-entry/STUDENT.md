# Unit 0：进入共享学习 Workspace

## 什么算完成

以下事实都由人实际检查过，才算完成本单元：

- GitHub 邀请确实已经接受，private repo 可以打开。
- 课程 repo 的本地绝对路径已经确认，不是 Codex 猜出的路径。
- 老师的 Codex、第一个人的 Codex、第二个人的 Codex 按顺序完成各自的加入步骤，每份申请都有老师填写的确认状态和批准范围。
- 你能打开 `CURRENT.md`、`TASKS.md`、`ROLES.md` 和自己的共享提交目录。

提交加入申请不等于已经加入。没有老师确认和实际文件证据时，只报告当前做到哪一步。

## 1. 先确认受邀和本地路径

本单元从“已经接受邀请”之后开始。如果邀请还没收到、还没接受，或 private repo 仍打不开，先停在这里，请老师处理访问问题。

新建个人知识库时，默认根目录是 `~/Obsidian/`。如果你已经有长期使用的个人知识库，继续使用原路径，不迁移。

三类目录的职责不同：

| 位置 | 放什么 |
| --- | --- |
| `<个人知识库>/Learn/Wiki/` | 长期积累的个人知识 |
| `<个人知识库>/Learn/Agent 101/` | 自己的课程笔记、反思和练习 |
| `<个人知识库>/Projects/AI Agent Learning Workspace/` | 本课程 repo、任务和共享协作状态 |

让 Codex 报告当前 repo 的本地绝对路径，再由你在 Obsidian 中打开同一位置。不要把课程 repo 复制到 `Learn/Agent 101/`。

## 2. 找到课堂入口和自己的提交目录

在 `course-workspace/` 中实际打开：

- [CURRENT.md](../../CURRENT.md)：已经确认的当前事实。
- [TASKS.md](../../TASKS.md)：现在要做的事。
- [ROLES.md](../../ROLES.md)：谁能修改哪些文件。
- [JOIN.md](../../JOIN.md)：三个 Codex 的加入顺序和申请格式。

自己的共享提交目录只有一个：

| 你代表谁 | 共享提交目录 |
| --- | --- |
| 第一个人 | `course-workspace/outputs/person-1/` |
| 第二个人 | `course-workspace/outputs/person-2/` |

个人完整笔记仍放在 `<个人知识库>/Learn/Agent 101/`。共享 `outputs/` 只放课堂明确要求共享的提交。

## 3. 三个 Codex 逐个加入

严格按顺序进行：

1. 老师的 Codex 先读取入口和角色文件，只创建自己的加入申请。
2. 老师检查第一份申请后，第一个人的 Codex 再创建自己的加入申请。
3. 老师检查第二份申请后，第二个人的 Codex 再创建自己的加入申请。
4. 老师逐份确认身份和权限；没有确认的 Codex 不能修改共享状态。

每个 Codex 只能创建自己的申请，不能代替另外两个 Codex 写占位文件。文件在一台电脑上出现，也不代表其他电脑已经同步收到。

## 4. 人工打开并检查

请逐项实际操作：

- 在 Obsidian 中打开课程 repo，并核对 Codex 报告的绝对路径。
- 打开 `CURRENT.md`、`TASKS.md` 和 `ROLES.md`，说出三者分别负责什么。
- 打开自己的 `outputs/person-N/`，确认没有进入另一人的目录。
- 打开已经真实创建的加入申请，核对它代表谁、申请什么权限。
- 对尚未发生的邀请、同步或加入，保留为“未完成”，不要补写成已完成。

## 遇到阻塞时

- 邀请或 private repo 访问失败：停在 GitHub 访问步骤，请老师处理；不创建加入申请。
- repo 还没安装到 Obsidian：回到受邀后安装入口，先确认个人知识库路径，再执行安装。
- 暂时无法同步：可以只做本地路径和文件定位，但不能声称三个 Codex 已加入同一个 Workspace。
- 某个 Codex 暂时不可用：记录缺少哪一个，已完成的 Codex 不代写它的申请。
