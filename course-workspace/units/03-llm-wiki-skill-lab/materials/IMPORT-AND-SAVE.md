# 外部 Skill 的导入与保存

## 先理解“导入”和“安装”

```text
发现：知道候选 Skill 在哪里
导入：把候选内容保存到个人草稿区，准备检查
安装：明确同意后，让 Codex 把通过检查的 Skill 放入自己的 Skill 目录
```

把 GitHub 链接发给 Codex 不等于已经安全导入；把文件下载到本机也不等于已经安装。

## 个人暂存位置

先把候选 Skill 保存在个人 Obsidian 知识库中：

```text
<个人 Obsidian 知识库>/Learn/Agent 101/Skills/Inbox/<skill-name>/
  SOURCE.md
  SKILL.md
  REVIEW.md
```

- `SOURCE.md`：原始链接、作者、repo、版本或 commit、查看日期、许可证信息。
- `SKILL.md`：候选正文；不要在审查时偷偷改成自己的版本。
- `REVIEW.md`：用途、权限、风险、试用结果和是否安装的决定。

个人草稿和审查记录不放进课程 repo；需要交流时在课堂中直接展示个人文件。

## 六步流程

1. **追到原始来源**：从推荐文章回到作者或 repo，记录具体文件链接和版本。
2. **保存完整依赖**：读取整个 `SKILL.md`，以及它引用的脚本、模板和参考文件。缺失依赖时不安装。
3. **做权限审查**：确认是否联网、读私人文件、改配置、安装软件、删除、提交、推送或发消息。
4. **用小任务试用**：默认手动调用，在非敏感材料上试一次，记录它实际读了什么、写了什么和哪里出错。
5. **由人决定**：明确写“暂不安装”或“同意安装”。沉默不是同意。
6. **安装并留坐标**：使用 `skill-installer` 或当前 Codex 支持的方式安装，记录本地路径、来源和验证结果。

## 给 Codex 的审查提示词

```text
请先不要安装或执行这个外部 Skill。

来源：[粘贴原始文件或 repo 链接]
个人暂存目录：[填写绝对路径]

请读取完整 SKILL.md 及其引用文件，然后写 REVIEW.md，回答：
1. 它什么时候触发，什么时候不该触发？
2. 它会读取、写入、联网或执行什么？
3. 是否包含删除、配置修改、commit、push、发消息或敏感数据风险？
4. 缺少哪些依赖、许可证或来源信息？
5. 最小试用任务是什么，怎样判断结果？

完成审查后停下来，等待我决定。不要安装、复制到 ~/.codex/skills、执行脚本、commit 或 push。
```

## 安装后的检查

- Codex 能报告实际安装路径。
- Skill 的名称、触发说明和来源仍可查到。
- 用同一个小任务再运行一次，比较安装前后的行为。
- 如果行为不符合预期，先停用并保留审查记录，不直接删除证据。

Skill 会更新。以后升级时重新检查变更，而不是因为旧版本可信就自动相信新版本。
