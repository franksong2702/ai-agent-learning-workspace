# Unit 5：Codex 执行任务

## 任务目标

先通过自然语言追问，与人达成对自由想法的共同理解；再形成工作说明、项目实现路径和下一周最小行动。不要只生成工作说明，也不要承诺或尝试现场完成完整项目。

## 前置

1. 读取同目录的 `STUDENT.md` 和 `templates/` 下三份模板。
2. 请人用原话说出想法，不要求提前整理。
3. 确认个人 Obsidian 知识库位置；未指定时建议 `~/Obsidian/`，但写入前仍要确认。
4. 确认项目名和个人项目目录：`<个人 Obsidian 知识库>/Learn/Agent 101/Projects/<项目名>/`。
5. 确认只可写个人项目目录，以及课堂明确要求的共享短摘要文件。
6. 如果目标文件已经存在，先报告路径并询问如何处理，不覆盖原内容。

## 执行顺序

### 1. 自然语言追问

- 一次只问一个问题，等待回答后再继续。
- 每个问题附一条推荐答案和简短理由，明确说明人可以采用、修改或否定。
- 根据已有回答选择下一个问题，不机械照抄固定问卷。
- 如果答案能从人已授权读取的文件中确认，先读文件，不重复提问。
- 至少澄清：希望发生的变化、使用或查看结果的人、第一份可见结果、现有输入、最小范围、暂时不做、验收证据和主要未知条件。
- 如果前面的回答已经覆盖某项，不为凑数量重复追问。

建议句式：

```text
我现在只确认一件事：______？
我的建议是______，因为______。你可以直接采用、修改或否定。
```

### 2. 确认共同理解

写文件前，先用不超过八行的自然语言复述：

- 要改变的事情。
- 谁会使用或看到结果。
- 第一个可见结果。
- 最小范围。
- 暂时不做。
- 验收证据。
- 仍待确认的假设。

最后只问：“这份理解准确吗？请指出要改的一处，或明确确认。”未得到确认时，继续单问单答，不生成正式文件。

### 3. 形成三份文件

得到确认后：

1. 使用 `templates/PROJECT-BRIEF.md` 生成工作说明。
2. 使用 `templates/PROJECT-PATH.md` 生成从当前状态到第一份可见结果的阶段路径。
3. 从路径中只选一个下一周最小行动，使用 `templates/NEXT-TASK.md` 写成可交给 Codex 的任务。
4. 三份文件写入 `<个人 Obsidian 知识库>/Learn/Agent 101/Projects/<项目名>/`。
5. 使用相对链接把三份文件互相连接。

### 4. 人工检查后再收口

逐份展示文件路径和核心内容，请人至少做一次保留、删除、改写或确认判断。根据反馈更新个人文件后，再报告实际写入结果。

只有课堂明确要求时，才在共享 workspace 写一份短摘要。短摘要只含：项目名、一句话目标、下一周最小行动和个人产物路径。

## 允许动作

- 在已确认范围内读取与想法直接相关的文件。
- 逐个追问并给出可被否定的推荐答案。
- 创建已确认的个人项目目录。
- 创建或修改本轮三份个人项目文件。
- 在课堂明确要求时创建一份共享短摘要。
- 根据人工反馈缩小范围、修改表述和补足验收标准。

## 禁止动作

- 不一次提出多个问题。
- 不在共同理解得到确认前写正式项目文件。
- 不编造目标、使用情境、来源、数据、文件或人工决定。
- 不直接开始写完整项目、批量生成代码或扩张功能范围。
- 不把“未来可能做”写成当前承诺。
- 不覆盖既有文件，不删除文件，不提交，不推送。
- 不读取或写入未授权目录，不索取或记录账号、密钥及其他敏感内容。
- 不把个人完整产物、私人反思或原始材料复制到共享 workspace。
- 不把 `Learn/Wiki/`、`Learn/Agent 101/` 和 `Projects/AI Agent Learning Workspace/` 当成同一种目录。

## 输出

个人完整产物目录：

```text
<个人 Obsidian 知识库>/Learn/Agent 101/Projects/<项目名>/
├── PROJECT-BRIEF.md
├── PROJECT-PATH.md
└── NEXT-TASK.md
```

课堂明确要求时可增加一份共享短摘要：

```text
<共享 workspace>/course-workspace/outputs/<你的目录>/unit-05-summary.md
```

不得在共享区增加三份个人完整产物的副本。

## 人工检查

请人逐项确认：

- 工作说明是否忠实于原话，而不是 Codex 自行补出的项目。
- 第一个可见结果是否能被打开、阅读、查看或操作。
- 最小范围和暂时不做是否明确。
- 项目路径的每一阶段是否有产物和检查点。
- 下一周最小行动是否只有一个主要动作。
- 验收标准是否能用文件存在、字段完整、页面可见、命令结果或人工判断来验证。
- 三个目录的职责是否分开。
- 共享短摘要是否移除了个人敏感内容。

未经人工确认，不要把任务描述为已经完成。

## 降级路径

### 想法过于模糊

先只问“你最希望哪件事情发生变化？”，给一个可撤回的建议。得到回答后，再问第一个可见结果，不要先做方案。

### 人暂时答不上来

提供两个差异明确的候选方向，推荐其中一个并解释理由，只让人回答当前选择。把未确定内容标成“待确认假设”，不能写成事实。

### 课堂时间不足

仍保留三份文件，但每份只填写核心字段。项目路径只写到第一份可见结果，`NEXT-TASK.md` 只保留一个下一周最小行动，不进入完整实现。

### 个人 Obsidian 知识库不可写

停止文件写入，在对话中给出三份草稿并明确标注“尚未落盘”。不要把完整草稿转存到共享 workspace。

### 共享 workspace 不可写

个人完整产物照常保留，报告共享短摘要尚未提交。不要为绕过故障复制到其他目录。

### 目标文件已经存在

不覆盖。报告冲突路径，先请人选择继续编辑、另建项目名或停止；未得到选择前不写入。
