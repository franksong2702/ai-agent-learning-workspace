# Unit 5：把自由想法变成项目路径

## 开始前准备 Skill

先按 [课程 Skill 地图](../../../SKILLS.md) 安装 `grill-me` 及其 `grilling` 支持依赖。两者缺一时不要开始追问流程。新开 Codex task 后，再把自己的原始想法交给它。

## 这次要得到什么

你可以带来一句还没想清楚的话，例如“我想做一个能帮我整理灵感的东西”。

明确告诉 Codex 使用 `grill-me` 后，它不会立刻开做，而是用自然语言一次问一个问题，等你回答后再继续。每次提问时，它会给出一个推荐答案和理由；你可以采用、修改或否定。

本单元结束时，你会得到三份互相连接的文件：

1. `PROJECT-BRIEF.md`：工作说明，讲清楚做什么、给谁用、最小范围和验收标准。
2. `PROJECT-PATH.md`：实现路径，讲清楚从现在到第一个可见结果要经过哪些阶段。
3. `NEXT-TASK.md`：下一周最小行动，只保留一个可以检查的动作。

本单元不要求现场完成完整项目，也不会只停在一张工作说明上。

## 一键复制给 Codex：开始 Unit 5

把自己的模糊想法放在最后一行，再复制整个代码块。Codex 会一次只问一个问题；在你确认它的理解前，不应该生成正式文件。

```text
请带我完成 Agent 101 的 Unit 5。

请先读取：
- 课程 repo 根目录的 SKILLS.md
- 当前 Unit 的 STUDENT.md 和 AGENT-TASK.md
- 当前 Unit templates/ 中的 PROJECT-BRIEF.md、PROJECT-PATH.md、NEXT-TASK.md

然后严格按以下方式协助：
1. 检查 grill-me 和它依赖的 grilling 是否可用；缺少任一个就停下报告，不要假装已使用该 Skill。
2. 请我确认个人 Obsidian Vault 的绝对路径和个人产物目录。课程 repo 保持只读。
3. 明确使用 grill-me 帮我梳理下面的原始想法。一次只问一个问题，等我回答后再继续；每次给一个推荐答案和简短理由，允许我采用、修改或否定。
4. 根据我的回答决定下一问，不机械照抄问卷，也不替我编造目标、对象、材料或限制。
5. 写文件前，用不超过八行复述目标、使用情境、第一个可见结果、最小范围、暂时不做、验收证据和待确认假设。只有我明确确认后才能继续。
6. 我确认后，按三个模板生成 PROJECT-BRIEF.md、PROJECT-PATH.md、NEXT-TASK.md，写入 <个人 Obsidian 知识库>/Learn/Agent 101/Projects/<项目名>/，并用相对链接互相连接。
7. 文件已存在时不要覆盖；先报告并让我选择。不要 commit、push、删除文件或开始开发完整项目。
8. 最后逐份让我检查，至少完成一次保留、删除、改写或确认判断，再报告实际文件绝对路径和仍未确认项。

我的原始想法：<在这里用自己的原话写一句话>
```

## 先把想法讲清楚

先把原话填进上面提示词的最后一行，不必提前整理成专业表达。把完整提示词发给 Codex 后，只回答它当前提出的一个问题。

Codex 会根据你的回答逐步追问这些方向，但不会一次把问题全抛出来：

- 你希望什么事情发生变化？
- 谁会使用或看到结果？你自己也可以是使用者。
- 第一个能看见、打开或检查的结果是什么？
- 你现在已经有哪些材料、工具、时间或限制？
- 最小版本只做什么，暂时不做什么？
- 什么证据能说明这一小步达到了要求？
- 哪个未知条件最可能挡住下一步？

如果你说“不知道”，Codex 应先给出一个容易撤回的建议，再请你选择或修改。它不能替你编造事实。

开始写文件前，Codex 会先用几句话复述它的理解，并问你是否准确。只有你确认后，才进入工作说明和项目路径。

## 课堂动作

1. 用一句自然语言说出你的自由想法。
2. 回答 Codex 当前提出的一个问题。
3. 纠正 Codex 的复述，直到目标、对象、可见结果和边界都准确。
4. 用 `templates/PROJECT-BRIEF.md` 形成工作说明。
5. 用 `templates/PROJECT-PATH.md` 形成设计、结构、制作和验证路径。
6. 从路径中选出一个下一周最小行动，写入 `templates/NEXT-TASK.md`。
7. 亲自检查三份文件，至少指出一处要保留、删除或改写的内容。
8. 把个人完整产物留在个人 Obsidian 知识库，课程 repo 保持只读。

## 文件放在哪里

先使用 Unit 0 已确认的个人 Obsidian 知识库；新建时通常是 `~/Obsidian/`，已有长期知识库继续使用实际路径。个人完整产物放在：

```text
<个人 Obsidian 知识库>/Learn/Agent 101/Projects/<项目名>/
```

三个位置的职责不要混在一起：

| 位置 | 放什么 | 不放什么 |
| --- | --- | --- |
| `<个人 Obsidian 知识库>/Learn/Wiki/` | 可复用的概念说明、来源笔记和知识卡 | 当前项目的完整工作说明和任务跟踪 |
| `<个人 Obsidian 知识库>/Learn/Agent 101/` | 课程学习记录和个人项目完整产物 | 课程 repo 的副本 |
| `<个人 Obsidian 知识库>/Projects/AI Agent Learning Workspace/` | 只读课堂入口、任务页和模板 | 个人项目材料、私人反思和作业摘要 |

## 完成标准

- 个人项目目录中存在 `PROJECT-BRIEF.md`、`PROJECT-PATH.md` 和 `NEXT-TASK.md`。
- 工作说明写清楚目标、使用情境、第一个可见结果、最小范围、暂时不做和验收标准。
- 项目路径至少包含设计或内容方向、结构、第一份产物和验证四个阶段。
- 下一周最小行动只有一个主要动作，并写明输入、输出、边界和检查方式。
- 你亲自确认过 Codex 对想法的复述，并检查过最终文件。
- 课程 repo 中没有个人完整产物、短摘要或个人产物路径。
